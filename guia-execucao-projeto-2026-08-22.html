Como colocar o sistema para rodar

Passo a passo para deixar as três partes do sistema funcionando em um computador: o banco de dados (onde as informações ficam guardadas), o backend (a "porta de entrada" que processa os pedidos) e o frontend (a tela que o usuário usa no navegador).

•Visão geral das três partes

O sistema é dividido em três peças independentes, que precisam ser ligadas nesta ordem: primeiro o banco de dados, depois o backend, e por último o frontend.

1. Banco de dados PostgreSQL

Onde ficam guardadas as informações de animais, adotantes, espécies e raças. Precisa estar rodando antes de qualquer outra parte, porque o backend se conecta a ele assim que é ligado.

2. Backend Java / Spring Boot

A "porta de entrada" do sistema (chamada tecnicamente de API). Recebe os pedidos vindos da tela, aplica as regras do negócio e conversa com o banco de dados. Fica localizado na pasta sistema-ong-animal.

3. Frontend Angular

A tela que o usuário efetivamente usa no navegador. Fica localizada na pasta sistema-ong-animal-frontend e depende do backend já estar rodando para funcionar de verdade (embora possa ser aberta sozinha).

Etapa 1 de 3

1Preparar o banco de dados

O backend usa o Flyway, uma ferramenta que cria e ajusta as tabelas do banco automaticamente assim que a aplicação é ligada — não é preciso criar tabela nenhuma manualmente. Só é necessário deixar um banco PostgreSQL disponível, na porta certa, e informar as credenciais de acesso.

1.1 — Confirmar que o PostgreSQL está instalado e rodando

No Windows, o PostgreSQL roda como um serviço. Para verificar se está instalado e ativo, no PowerShell:

Get-Service -Name '*postgres*'

O campo Status deve aparecer como Running. Se não aparecer nenhum serviço, o PostgreSQL precisa ser instalado primeiro.

1.2 — Descobrir a porta real em que ele está escutando

Este é o passo mais pulado e a causa mais comum de erro de conexão. A porta padrão do PostgreSQL é 5432, mas o instalador do Windows escolhe automaticamente outra porta (ex: 5433) quando a 5432 já está ocupada — o que é comum se já existir outra versão instalada. Nunca assuma que é 5432: confirme sempre no arquivo postgresql.conf da instalação, geralmente em C:\Program Files\PostgreSQL\<versão>\data\postgresql.conf:

Select-String -Path "C:\Program Files\PostgreSQL\*\data\postgresql.conf" -Pattern "^port"

Anote o número retornado — é ele que vai entrar na URL de conexão do backend, não o 5432 por padrão.

1.3 — Criar o banco de dados vazio para o projeto

Pode ser feito por qualquer ferramenta de administração (pgAdmin, DBeaver) ou direto pelo terminal com o psql. O psql normalmente não fica no PATH do Windows, então é preciso usar o caminho completo do executável (ajustando a versão na pasta):

& "C:\Program Files\PostgreSQL\<versão>\bin\psql.exe" -U postgres -h localhost -p <porta_anotada_no_passo_1.2> -c "CREATE DATABASE ong_animal;"

Isso vai pedir a senha do usuário postgres (definida na instalação do PostgreSQL). Para conferir que o banco foi criado, liste todos com -l no lugar do -c "CREATE DATABASE...".

  • PostgreSQL instalado e com o serviço em Running.
  • Porta real confirmada no postgresql.conf (não presumir 5432).
  • Banco de dados vazio criado (ex: ong_animal).
  • Anotar host, porta confirmada, nome do banco, usuário e senha — serão usados na configuração do backend na próxima etapa.
Não é preciso rodar nenhum script SQL de tabela manualmente. As tabelas e os dados iniciais são criados sozinhos pelo Flyway na primeira vez que o backend é ligado, a partir dos scripts versionados no repositório do backend. O único SQL manual necessário é o CREATE DATABASE do banco vazio, acima.
Etapa 2 de 3

2Ligar o backend

Repositório: sistema-ong-animal. Requer Java 17 instalado; o gerenciador de build (Maven) já vem embutido no projeto, não precisa ser instalado separadamente.

2.1 — Configurar o acesso ao banco de dados

O arquivo principal de configuração (application.properties) não traz credenciais de banco por padrão, por segurança. É preciso criar um arquivo próprio, que não entra no controle de versão, com as credenciais anotadas na etapa anterior:

Criar o arquivo src/main/resources/application-local.properties com o conteúdo, usando a porta confirmada na Etapa 1.2 (não copiar 5432 às cegas):

spring.datasource.url=jdbc:postgresql://localhost:<porta_anotada_no_passo_1.2>/ong_animal spring.datasource.username=SEU_USUARIO spring.datasource.password=SUA_SENHA
Erro mais comum aqui: deixar 5432 fixo na URL sem checar a porta real do serviço instalado. Isso causa Connection refused ao iniciar o backend, mesmo com o PostgreSQL rodando normalmente — porque a aplicação está tentando falar com a porta errada.

2.2 — Executar a aplicação

Dentro da pasta sistema-ong-animal, no terminal:

.\mvnw.cmd spring-boot:run

Na primeira execução, o Flyway cria automaticamente todas as tabelas e alguns dados iniciais de exemplo. O backend fica disponível em http://localhost:8080.

Como saber que deu certo: o terminal mostra o log de inicialização do Spring Boot terminando com uma linha do tipo "Started SistemaOngAnimalApplication" e nenhum erro de conexão com o banco.

2.3 — Solução de problemas mais comuns

Connection refused ao conectar no banco

A porta usada em application-local.properties não é a porta real em que o PostgreSQL está escutando. Repetir o passo 1.2 para confirmar a porta e corrigir a URL.

database "..." does not exist

O banco vazio ainda não foi criado (passo 1.3 pulado) ou o nome usado na URL não é exatamente igual ao nome criado no PostgreSQL.

Port 8080 was already in use

Já existe outro processo Java do backend rodando (por exemplo, uma execução anterior que não foi encerrada corretamente). Encontrar e encerrar esse processo antes de rodar de novo:

Get-NetTCPConnection -LocalPort 8080 | Select-Object -ExpandProperty OwningProcess -Unique | ForEach-Object { Get-Process -Id $_ } Stop-Process -Id <id_encontrado_acima> -Force
Etapa 3 de 3

3Ligar o frontend

Repositório: sistema-ong-animal-frontend. Requer Node.js instalado (para ter o npm, gerenciador de pacotes usado pelo Angular).

3.1 — Instalar as dependências

Só precisa ser feito uma vez (ou quando novas bibliotecas forem adicionadas ao projeto). Dentro da pasta sistema-ong-animal-frontend:

npm install

3.2 — Iniciar a tela

npm start

A tela fica disponível em http://localhost:4200, aberta no navegador. Ela já vem configurada para conversar com o backend em http://localhost:8080 — por isso o backend precisa estar ligado antes.

Atenção à porta: o backend só aceita pedidos vindos de http://localhost:4200 (regra de segurança chamada CORS). Se a tela abrir em outra porta, os pedidos ao backend serão bloqueados pelo navegador.

✓Checagem final

Com as três partes ligadas, nesta ordem: banco de dados → backend → frontend.

  • PostgreSQL em execução, com o banco de dados criado.
  • Backend rodando em http://localhost:8080, sem erros no terminal.
  • Frontend rodando em http://localhost:4200, exibindo a lista de animais sem a mensagem de "backend não está rodando".
